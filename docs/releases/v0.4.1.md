# CLIProxyAPIPlus v0.4.1

## Portable 程序包

本版补齐三个原生目标的完整程序包。请下载 **Assets 中的 Portable 附件**，而不是 GitHub 自动生成的 Source code ZIP / TAR.GZ。

| 系统 / 架构 | 文件 |
| --- | --- |
| Windows x64 | `CLIProxyAPIPlus_0.4.1_windows_amd64_portable.zip` |
| Linux x64 | `CLIProxyAPIPlus_0.4.1_linux_amd64_portable.tar.gz` |
| Linux ARM64 | `CLIProxyAPIPlus_0.4.1_linux_arm64_portable.tar.gz` |

每个包附 `.sha256`；`SHA256SUMS` 汇总三包摘要，`release-manifest.json` 记录提交、平台、程序/归档/配方摘要及原生工程检查。Linux 内置 SDK 要求 glibc 2.28+；没有 macOS、Windows ARM64 或 musl 包。

## 修复与发布约束

- 原有工作流只上传验证元数据，成功构建也不会产生 Release 程序附件；本版增加独立的手动 Portable 发布流程。
- 发行要求相同 master 提交的完整 verify 工作流通过。三个目标在对应原生 runner 构建并重跑 SDK/配方、二进制和维护 smoke；所有包齐全、逐文件摘要校验通过后才公开 draft。
- 普通验证与上游候选仍使用元数据白名单；发布写权限仅授予最终 publisher，不用于执行 Go/npm/上游测试。不公开原始日志、认证文件或运行数据。
- Linux race 的包级预算增至 30 分钟，保留 race、原 fixture 和断言；非 race 保留完整范围并设置 20 分钟预算。
- Windows 恢复遇到短暂的已还原文件读者时，只重试指定 Win32 竞争错误，最多等待 1.55 秒；持续拒绝仍失败，不改 ACL、不覆盖已有目录，并校验 staging 身份。
- 源码构建失败只导出已知测试名和固定信号枚举，不公开私有日志。

## 安装与升级

先核对归档 SHA256，再解压到新目录。保留 `build-tools/`、`update-tools.json`、`updater-source/`，不可仅复制主程序。包内附 Python、Go、Node/npm；使用者无需另行下载 SDK，但页面源码升级仍须联网获取上游源码和依赖，不需要额外发行服务。

`update-tools.json` 默认：

```json
{
  "bundle": "./build-tools",
  "go_proxy": "https://goproxy.cn|https://proxy.golang.org"
}
```

全新实例使用 README 的 `--init` 命令；已有实例不得重新初始化。更新已有部署前停机并备份原程序、配置、data.key、SQLite、认证文件及私有更新事务目录，按运维指南迁移到新包。不要把旧运行数据或旧 SDK 随意覆盖进新安装包。

历史 v0.4.0 保持源码发行和原标签，不把新二进制改名塞入旧版本。

## 验收边界

发行工程验证不等于所有生产环境准入。真实供应商/OAuth、用户历史库迁移、24h 混合故障、Full/插件/容器和性能 SLO、安全/法律及新增产品代码许可证决策仍须按具体环境签收。SBOM、许可索引、上游原始许可和 SDK notices 随包保留，不把构建成功当作法律或安全审批。
