# 网页整包升级扩展（2026-11-04）

用户要求在页面上提醒、执行升级与回滚。本扩展替代原计划“页面只读、离线安装”的限制；不改变双上游源码候选流程，不在运行时编译上游，不发布或升级当前用户实例。

- 沿用 CPA Manager 的更新页与 DB-backed 管理员认证，所有执行接口在 `/plus-api/releases/operations` 下；不接受浏览器提供的路径、命令或下载地址。
- 后台定期检查操作者指定的产品索引（默认 HTTPS，本机 HTTP 例外见下文），前端全局提醒与更新页共享状态；检查失败标记陈旧，安装前重新检查版本与包摘要。
- 独立 Portable 进程显式使用 `--web-updates` 开启执行能力。容器/systemd/Windows Service 的进程管理需由部署系统负责，本模式不能混用外部自动拉起。
- 只接受当前 OS/ARCH 的 Portable 包，限制包体/解压大小和条目，拒绝链接/路径逃逸，核对 SHA256、程序身份与更新协议。索引及包来源必须由操作者信任；HTTPS+摘要不等于发行签名，签名/生产准入仍是未完成门禁。
- 临时辅助进程由同一可执行文件的私有副本启动，不需要 Python/Node；正常运行不新增监听端口。握手成功后请求旧程序正常排空，辅助进程等旧进程真正退出后才操作文件。
- 使用原 Manager 跨进程数据库锁。维护标记阻止普通实例抢先启动；更新操作有单独 OS 锁、私有状态目录与事务记录。备份整个已关闭的数据目录、配置与旧程序，校验清单后迁移及重启。新进程必须持有对应一次性激活标识，辅助进程验证版本、就绪及新进程握手。
- 自动回退与手动回滚成对恢复程序/配置/数据，保留失败版本的数据，不只回退二进制。网页回滚限于匹配当前程序摘要的最近成功升级；回滚前明确确认会丢失快照之后的逻辑数据。
- 为保持备份边界明确，网页安装仅支持认证目录/TLS材料位于 data-dir 内的自包含部署；外置材料继续使用原离线工具。拒绝符号链接、重叠安装/状态/数据路径、非标准参数或不能识别的旧程序。
- 中断时保留事务/维护标记，不假装成功；提供离线恢复入口。校验失败不停止旧服务，备份失败不安装新程序，不能确认恢复时停在 recovery_required。
- 验证必须覆盖管理员/来源/并发/摘要/压缩包边界、失败恢复、真实 Windows 临时实例升级及回滚、前端确认与重连；Linux仅交叉构建不宣称原生验收。

补充 Windows 与持久化保护：Go 普通只读句柄不共享删除权限，状态轮询可能与原子替换竞态。维护记录采用共享删除读取、读取后关闭再解析；Windows 原子替换使用原生 POSIX 语义，使旧读句柄与新记录并存，并对短时共享/访问失败有限重试，不绕过永久 ACL 失败。写入记录不得超过读取上限，过大的快照清单在安装前拒绝。已有状态目录/记录须由当前账户或可信系统管理员拥有，不能仅靠重设 DACL 接管他人事务。安装、配置、数据和这些目录的父目录必须禁止不可信本机用户写入；管理员/发行源仍属于显式信任边界。

健康请求使用冻结监听器的真实 IP/端口（通配地址用对应地址族的回环地址），不假设明确绑定的 LAN/127.0.0.2 等地址同时监听 127.0.0.1。hostname/动态端口模式拒绝网页执行并保留离线路径。TLS 健康检查只在专用自监听传输中固定配置的叶证书，不替换全局客户端。


## 本机 HTTP 扩展（0.3.0-rc.2）

用户明确要求本地页面升级。默认 HTTPS 不变；显式 `--allow-local-release-http` 仅放行回环 IP 字面量，同源 HTTP 包/重定向，不涉及全局传输或管理员授权放宽。源码身份可使用已验证发行包内真实 `product_source_sha256`，无须虚构 Git 提交；安装时匹配候选 binary 身份。完整配置见 [LOCAL_WEB_UPDATES_CN.md](LOCAL_WEB_UPDATES_CN.md)。首次进入支持本开关的版本仍需手动/离线替换，后续走网页事务。
