## 核心实现说明

1. Core SDK 持有唯一 HTTP/RESP 业务监听器；Manager 只发布 handler，不另开常驻业务端口。数据面仍走核心协议栈。
2. 内部 Transport 只允许固定虚拟主机与已批准路径。Go 私有上下文只跳过 Manager 分发，**不跳过核心认证**；不修改 `http.DefaultTransport`/`DefaultClient`。
3. 公共管理请求依旧经过 Manager 的管理员/认证文件保护；v8 仅保留其支持的 provider 配置子树和核心公开 OAuth callback 边界。
4. `/plus-api/releases`、`/plus-api/runtime` 使用 Manager 数据库验证器，管理员凭据变化后不继续信任旧 bootstrap key；公开版本/就绪不泄露内部明文。
5. 原生解析、配置文件加载、保留注释的保存及 SDK 热应用共同校验单监听器/凭据边界；拒绝危险设置不能修改磁盘文件。策略安装互斥且旧清理句柄不能移除新策略。
6. 独立 Manager 入口也复用共享 runtime；监听绑定和 handler 发布先于较重的 post-listen 维护，避免让旧部署长时间无法打开进度页面。源代码结构断言已随共享抽取更新，而非删除对应约束。
7. 后台任务按 group 拥有上下文与计数，panic 会通知 supervisor；有界排空未完成时不假装关闭数据库成功。WAL 维护连接在任务排空后、主库/锁之前关闭。
8. 前端保留原 Card/Button/主题；`__APP_VERSION__` 保持真实 Manager 版本，产品版本从独立 API 读取，避免生成指向上游的虚假 0.2.0 release 链接。核心更新按钮转到整包更新页。
9. Windows 产品目录、密钥与维护备份使用原生受保护 DACL；Python 工具显式设置 ACL，不依赖 Python `chmod(0600)` 的 Windows 表象。POSIX 使用 0700/0600。
10. 升级默认 dry-run，要求可信 SHA256；旧程序与一致性数据快照成对保存，离线迁移失败自动回滚，成功后仍需操作者重启并检查健康。
